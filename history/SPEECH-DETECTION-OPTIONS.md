# Speech detection for subtitle review

Research and local comparison checked 2026-09-27. A voice detector finds possible speech; it cannot verify words or prove silence. The release decision still depends on the video audio. The [three-episode benchmark](pilots/vad-window-benchmark-2026-09-27/REPORT.md) records the measured intervals and scan times.

## What Episode 39 taught us

The installed source SRT has no cue from 21:17.414 to 22:51.829. The [five-minute Silero scan](pilots/source-review/039/speech-coverage.json) found no speech at 22:45–22:51. A fresh **24-second clip of the same video**, scanned with the same Silero v6 model and 0.5 threshold, detected speech starting at **22:45.28**. Thresholds 0.3 and 0.2 found essentially the same onset. A local Whisper large-v3 pass **without VAD** recovered candidate opening dialogue, including “Ne haber abi?” and “İyi. Neyin var senin?” Whisper placed its first line at the clip start, earlier than Silero's onset, so the wording and boundaries still need audio review. The downloaded English reference also contains this exchange, but its clock is offset from the video. In a later [transcription comparison](pilots/source-separation-2026-09-27/transcription-comparison/REPORT.md), Deepgram found the opening in a five-minute original-audio window while Whisper missed it on both original and Demucs-separated audio; focused Whisper recovered it.

This is a **window-dependent miss** in the current scan, not evidence that Silero v6 is inherently unable to hear the scene. Lowering one threshold on the five-minute scan has not been shown to fix it. The new workbench queue therefore flags long subtitle-free spans without relying on VAD, then lets a reviewer examine the whole span, compare a reference, and use a short-window VAD or no-VAD ASR pass as additional evidence.

## Candidate detectors

| Option | What the official source establishes | Fit for this workflow |
| --- | --- | --- |
| **Silero v6, already installed** | Silero publishes multi-domain quality results and documents tuning the speech threshold and minimum durations. [Quality metrics](https://github.com/snakers4/silero-vad/wiki/Quality-Metrics), [tuning FAQ](https://github.com/snakers4/silero-vad/wiki/FAQ) | Keep as the baseline. The Episode 39 short-window result shows that scan design matters as much as model choice. |
| **FireRedVAD, local** | The project reports 97.57% F1 versus 95.95% for Silero on its FLEURS-VAD-102 test and provides a separate audio-event model for speech, singing, and music. Its test-set release was still marked “coming soon” in the project description. [Project and evaluation](https://github.com/FireRedTeam/FireRedVAD), [model card](https://huggingface.co/FireRedTeam/FireRedVAD), [license](https://github.com/FireRedTeam/FireRedVAD/blob/main/LICENSE) | **Locally tested on episodes 38–40:** five-minute scans found the E39 missed opening at 22:45.19, covered 4,916/4,979 existing cues, and averaged 22.1 seconds per episode. The same Silero scan missed that opening, covered 4,787 cues, and averaged 32.1 seconds. FireRed also raised more music/noise candidates, so detections still need review. |
| **pyannote voice activity detection, local** | Its model card shows excerpt and full-file inference, but requires accepting model access conditions and obtaining a token. [Model card](https://huggingface.co/pyannote/voice-activity-detection) | Another independent candidate if FireRedVAD misses important cases; more setup than the present CLI. No series-specific result yet. |
| **pyannoteAI, hosted batch** | Its hosted diarization accepts a completed audio file and returns timed speaker segments. Batch processing is supported; transcription is optional. [Model overview](https://www.pyannote.ai/md/models), [batch job example](https://www.pyannote.ai/blog/oss-model-api) | Best hosted comparison for speech intervals independent of recognized words. No episode audio was uploaded or billed. |
| **Deepgram prerecorded transcription, hosted** | Its prerecorded API accepts a local audio file and can return utterance start/end times and word timings. [Utterances](https://developers.deepgram.com/docs/utterances), [prerecorded API](https://developers.deepgram.com/reference/speech-to-text/listen-pre-recorded) | Tested on labelled short clips and five-minute windows. It found the Episode 39 opening on original audio, but other five-minute windows started late or omitted words, and high-confidence false words appeared over confirmed music. Use it as an independent review lead, never a silence or wording verdict. |
| **Google Cloud batch transcription, hosted** | Batch recognition handles long recordings and can return word time offsets. [Batch recognition](https://cloud.google.com/speech-to-text/docs/batch-recognize), [word timestamps](https://docs.cloud.google.com/speech-to-text/docs/v1/async-time-offsets) | Another transcript-based batch comparison; it is not a standalone batch VAD result. No live test was made. |
| **Google Cloud speech activity events, hosted** | Speech-start and end events are available for **streaming** recognition. [Google documentation](https://docs.cloud.google.com/speech-to-text/docs/voice-activity-events) | Less convenient for already-downloaded episodes; it would require sending audio to a hosted service and does not supply the missing words. No live test was made. |

## Decision and next comparison

Keep the **subtitle-gap and reference checks independent of every detector**. The local test favors FireRed's five-minute windows for a full speech map; shortening its windows to 90 seconds found no extra cue-timed speech and was slower. For a video that already has subtitles, a FireRed pass on subtitle-free gaps of at least 10 seconds caught the E39 miss in three seconds of scanning. Listen to each candidate and use no-VAD transcription as another clue. The production scanner has **not** been changed yet.

The [human-labelled review](pilots/deepgram-human-review-2026-09-27/full-episode-38/REPORT.md) and [music-separation pilot](pilots/source-separation-2026-09-27/REPORT.md) add speech, music, and silence checks; neither proves complete episode coverage. Existing subtitle cues are an imperfect benchmark, and the tests did not measure total human review time. If a future check exposes material misses from local VAD, pyannoteAI batch remains a possible hosted VAD comparison. Its cost and data handling would need review before use.
