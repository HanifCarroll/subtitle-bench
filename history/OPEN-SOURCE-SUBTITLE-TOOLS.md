# Open-source tools for a language-neutral subtitle pipeline

Research checked 2026-09-25. This is a historical options review; several “still to build” notes below predate the one-video workbench. For current steps and tool status, use [SUBTITLE-PIPELINE.md](../SUBTITLE-PIPELINE.md) and [WORKBENCH.md](../WORKBENCH.md). The target is one video, with or without existing subtitle candidates, to a faithful source-language SRT and English SRT, both timed to speech. Speech fidelity comes before reading speed.

The intended operator is an **agent working through videos one at a time**. Software should expose existing-subtitle search, transcription, alignment, audit, translation, and promotion as separate actions with inspectable evidence. An audio-capable agent reviews uncertain speech, chooses repairs, and decides when to advance. Batch generation can make drafts, but it must not silently settle disputed speech or publish subtitle files.

## Main finding

We need less custom software than the pipeline document suggests. **Subtitle Edit 5** provides a macOS review interface with video, waveform, source/translation columns, timing warnings, and manual cue editing. We tested stable 5.2 on this Mac with three copied problem sections; see the [pilot report](pilots/subtitle-edit-ui/REPORT.md). Its error-list export copies tab-separated text to the clipboard. Its 5.3 beta adds a forced-alignment preview, but that feature requires roughly correct input text and may lengthen a cue for reading speed. Neither proves that all speech has been transcribed. [Platform and license](https://github.com/SubtitleEdit/subtitleedit/blob/main/docs/faq.md) · [5.2 changes](https://github.com/SubtitleEdit/subtitleedit/blob/main/Changelog.txt) · [quality report](https://github.com/SubtitleEdit/subtitleedit/blob/main/docs/features/speech-to-text.md) · [alignment behavior](https://github.com/SubtitleEdit/subtitleedit/blob/main/docs/features/improve-time-codes.md)

At the time of this research, `audit-speech-coverage.py` already accepted any video and SRT, while the one-video review queue was still planned. The current [workbench](../WORKBENCH.md) combines speech, subtitle, timing, repetition, and reference questions. The local coverage script still uses this Mac's FFmpeg and Silero paths; the public repository copy resolves executables from `PATH` and accepts `SUBTITLE_VAD_MODEL` for the model file.

Find existing source-language subtitles before transcription. A matching candidate may supply the main working text; a mismatched one can still reveal omitted dialogue. Check its cut, offset, advertisements, and wording against the video audio. The [Episode 1 OpenSubtitles candidate](https://www.opensubtitles.org/en/subtitles/9950948/leyla-and-mecnun-pilot-tr) was supplied as an example; its claimed timing mismatch and omissions have not been independently checked in this pilot.

The [real-audio pilot](pilots/audio-review/REPORT.md) ran local alternatives on copied Episode 38 and 5 clips. Qwen3-ASR 1.7B was useful as independent comparison text. Qwen2-Audio 7B and Qwen2.5-Omni 3B/7B failed on the Turkish seam. Qwen3-Omni 30B ran within this Mac's memory and gave a coherent main sentence after a decoding workaround, but missed or looped short replies. This Codex interface did not deliver audio to the agent, so the pilot did not establish an audio-based fidelity gate.

## Clip-boundary ideas to borrow

The current `combine-069-chunks.py` keeps a cue by its midpoint. That dropped words when an utterance crossed a five-minute boundary. `transcribe-loop-windows.py` now retains crossing cues from both clips, but leaves overlaps to review. The general joiner must keep the original two alternatives until their common speech is resolved.

- [CrisperWhisper 2](https://github.com/nyrahealth/CrisperWhisper/blob/main/DOCS.md) documents two useful strategies: carry confirmed trailing words into the next overlapping window, or independently decode windows and match their overlap by longest common word/token sequence. Its code is MIT, but **the standard model weights and their outputs have a non-commercial license**. Study the seam design; do not adopt its model as the default or copy implementation without checking notices and the exact license.
- [SimulStreaming](https://github.com/ufal/SimulStreaming) uses LocalAgreement: confirm a prefix only after successive audio windows agree. Current repository license is [MIT](https://github.com/ufal/SimulStreaming/blob/main/LICENCE.txt). This is designed for live streaming, so its confirmation rule is inspiration for an offline joiner, not a replacement pipeline.
- For our offline joiner, compare candidate words **within the same audio-time overlap** and record disagreements and boundary-spanning phrases. The current pilot retains both versions and exports seam audio; it does not collapse agreement or decide words. Repeated text elsewhere must stay unless the audio proves a duplicate transcription. Never rely on cue midpoint or text equality alone.

## Historical implementation gaps

These were the gaps recorded during the initial research. The current status is in [SUBTITLE-PIPELINE.md](../SUBTITLE-PIPELINE.md).

1. **Resolve recorded seam decisions:** the [pilot joiner](../scripts/join-clip-drafts.py) now accepts clip transcripts, offsets, and source language, then outputs a draft SRT plus both alternatives and seam audio. It leaves duplicates visible. An audio-capable reviewer still needs to decide the words, then apply that decision to a clean draft. Episode 38 near 01:20 is the first regression case.
2. **One review queue:** combine the existing `subtitle-timing.py` duration/overlap checks, `audit-speech-coverage.py` VAD-only intervals, joiner disagreements, and alignment outliers. Each row links to an audio time. Subtitle Edit can be the review UI, so first test whether its export and navigation cover the human work before building another one.
3. **Agent-operated one-video workbench:** expose each existing stage as a callable action with its draft and evidence, plus a promotion command. Adapt `promote-aligned-subtitles.py` to accept arbitrary language-tagged files, independently segmented English, input hash, review decisions, and backups. Do not require equal source/English cue counts or identical times. The agent explicitly calls promotion for reviewed candidates; validation and backup run before installation. A simple manifest suffices to resume work.

These are smaller than replacing the current ASR, aligner, translation script, or media player. `whisply` and other one-command subtitle generators can prepare drafts; they do not give the agent the audio evidence and control needed to settle speech-fidelity questions.

## Alternatives to keep conditional

- [stable-ts](https://github.com/jianfch/stable-ts) provides alignment and regrouping, but its repository was [archived in May 2026](https://github.com/jianfch/stable-ts/blob/main/LICENSE). Keep it as a comparison tool already used, not a new core dependency.
- [Argos Translate](https://github.com/argosopentech/argos-translate) is an MIT/CC0 offline translation library. The project's [model-package licensing is unresolved in its issue tracker](https://github.com/argosopentech/argos-translate/issues/533); translation quality and dialogue fidelity also need a direct test. Keep DeepSeek Flash as the known current translation path for now.
- [Aegisub](https://github.com/TypesettingTools/Aegisub) is a capable manual editor, but Subtitle Edit 5 more directly covers this review workflow and has an Apple Silicon package. Aegisub's distributed builds can be GPL due to bundled FFTW.

## Pilot evidence

The [agent UI pilot](pilots/subtitle-edit-ui/REPORT.md) used copies of Episode 38's clip boundary, Episode 5's repeated-line loop, and Episode 69's early cue. Subtitle Edit opened the clips, navigated warnings, and saved an English text and timing edit without changing the source file on disk. It did not supply audio content to the agent through the computer-use interface, so listening-based judgments remain untested. Use it as an optional editor; the agent workbench still needs audio clips and a review queue that puts speech uncertainty ahead of reading-speed notices. Compare another ASR implementation only on a disputed clip after the agent can inspect its audio.

The app was run from a mounted official disk image, with no permanent installation. The later [local model and joiner pilot](pilots/audio-review/REPORT.md) tested real audio and preserved an unresolved seam. Original episode media and subtitle sidecars were not modified.
